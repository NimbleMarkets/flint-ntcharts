# booba-shim `flintchart` Implementation Plan (flint → ntcharts, Phase 6)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Browser Go-WASM apps get flint compilation through a booba-shim subpackage: `flintchart.Compile(ctx, input) ([]byte, error)` calls the flint-chart JS (vendored ESM bundle built from flint-ntcharts's own compile source) via `globalThis.boobaShim.flintchart`, returning the same frozen envelope the native wasm path emits — identical by construction, since both bundles share `compileToNtSpec`.

**Architecture:** Four moves. (1) flint-ntcharts refactor: a dependency-light `envelope` leaf package (Warning/Size/Parse + the JSON option injectors) so parsing the envelope never links wazero or the 3 MB embedded wasm; `tui` gains a `Compiler` interface (native `*compile.Runner` satisfies it) and `sources.go` gets `//go:build !js`. (2) flint-ntcharts browser entry: `entry-browser.ts` registers `globalThis.boobaShim.flintchart = {compile, version, ready}` (compile is SYNC — assembleNtcharts is pure computation), built by esbuild to a self-contained ESM, smoke-tested in Node, provenance-stamped. (3) booba-shim (branch `flintchart`): vendored asset under `web/flintchart/` + embedded mirror, Go package on the pdfium pattern (lazy `ensureReady`, `awaitPromise`, `callSync` throw-recovery, `!js` stubs). (4) Example + docs per repo conventions.

**Tech Stack:** existing. No new deps in booba-shim (syscall/js only); esbuild ESM target in flint-ntcharts.

**Design refs:** design §5 (booba-shim pattern); booba-shim's own pdfium spec/plan (`booba-shim/docs/superpowers/`); P5 final-review Phase-6 notes (Compiler interface, sources isolation).

- Bridge protocol (matches pdfium conventions): global key `globalThis.boobaShim.flintchart` with members `compile(inputJSON string) → string` (synchronous; throws on JS exception — Go recovers via callSync), `version → string`, `ready → Promise` (resolved at module load; awaited once in `ensureReady`). - The envelope contract is FROZEN (P4): success `{spec, warnings, size}`, failure `{"error":{"message"}}`. The shim returns whatever compile() returns, verbatim. Error-envelope handling belongs to callers (envelope.Parse surfaces it as a Go error).

- Build tags follow booba-shim convention: `//go:build js` / `//go:build !js` (no `&& wasm`).
- pdfium-pattern anchors (transcribe conventions from these, adapting names): `booba-shim/pdfium/bridge_js.go:21` (ensureReady), `:48` (awaitPromise), `:99` (callSync), `:83` (mapJSError), `pdfium/errors.go`, `pdfium/document_other.go` (stubs), `web/pdfium/pdfium-shim.js:11,184` (registration), `cmd/booba-shim-assets/main.go:54` + `embedded.go:8` (assets are data-driven off `assets/<shim>/` — no registry to edit).

```go
//go:build js

package flintchart

import (
	"context"
	"syscall/js"
)

func Compile(ctx context.Context, input []byte) ([]byte, error) {
	bridge, err := ensureReady()
	if err != nil {
		return nil, err
	}
	if err := ctx.Err(); err != nil {
		return nil, err
	}
	res, err := callSync(bridge, "compile", string(input))
	if err != nil {
		return nil, err
	}
	return []byte(res.String()), nil
}

func Version() (string, error) {
	bridge, err := ensureReady()
	if err != nil {
		return "", err
	}
	v := bridge.Get("version")
	if v.Type() != js.TypeString {
		return "", &Error{Message: "bridge has no version string"}
	}
	return v.String(), nil
}
```

```go
func setText(id, text string) {
```
